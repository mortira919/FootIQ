# Промпт: полная проверка FootIQ API /v1

Ты тестируешь бэкенд FootIQ. Твоя задача: доказать, что сервер отвечает ровно по контракту `API.md` при любом вводе, и найти всё, где он ломается. Отчёт строится из воспроизводимых запросов, ответов и ссылок на строки кода. Догадки в отчёт не идут.

## Контекст

FootIQ это тактический тренажёр для футболистов. Игрок выбирает амплуа, решает 2D-сцены (куда отдать пас или открыться), проходит Rush на скорость и разбирает видео с AI-тренером. За попытки сервер двигает рейтинг.

Клиент на Flutter уже написан под `API.md` и ждёт сервер по адресу из `--dart-define=API_URL`. Всё, что влияет на рейтинг (ELO, серия, лимиты, PRO, исход задачи), считает сервер. Клиент шлёт только сырые действия.

Стек сервера: Python 3.13, FastAPI, SQLite, PyJWT. Код:

| Файл | Что там |
| --- | --- |
| `backend/app/v1.py` | Все ручки `/v1`, форма ответов, проверки ввода, перевод кодов ролей |
| `backend/app/store.py` | SQL: игроки, токены, попытки, сессии режимов, лиги |
| `backend/app/geometry.py` | Судья сцены `judge()`: исход и причина по точке игрока |
| `backend/app/glicko.py` | Glicko-2, старт 800, RD 350 |
| `backend/app/video.py` | Рубрика видеоразбора по ключевым словам (LLM пока нет) |
| `backend/app/main.py` | Старый стенд без префикса. Его ручки должны работать как раньше |
| `backend/puzzles/*.json` | 10 сцен, по одной на роль |
| `backend/puzzles_video/*.json` | Один видеоразбор, роль `dm` |
| `backend/tests/` | Уже написанные тесты, `test_v1*.py` про `/v1` |

Запуск:

```bash
cd backend
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv/Scripts/pip
PYTHONPATH=. .venv/bin/python -m unittest discover -s tests
PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8000
```

Вход через Google и Apple проверяет подпись токена по JWKS провайдера. В тестах подмени `app.v1.verify_identity` или положи свой RSA-ключ в `app.v1._jwks[url]`, как это сделано в `tests/test_v1_matrix.py`. Сеть для тестов не нужна.

### Словарь сервера

| Понятие | Значение |
| --- | --- |
| Роли клиента | `gk`, `cb`, `fb`, `dm`, `cm`, `am`, `wm`, `winger`, `st`, `ss` |
| Роли в базе | `fb` = `rb/lb`, `wm` = `lm/rm`, `winger` = `lw/rw`, остальные совпадают. Наружу базовые коды не выходят никогда |
| `sceneId` | Код роли клиента. Сцена `fb` хранится как `rb-channel-1` |
| Исход | `gold` (1), `silver` (0.5), `error` (0) |
| Причины | `optimal`, `safe`, `timeout`, `out`, `noReceiver`, `offside`, `cone`, `shadow`, `marked` |
| Тренеры | `base` (Free), `pep`, `jose`, `jurgen` (только PRO) |
| Регионы | `Россия`, `Казахстан`, `Беларусь`, `Узбекистан`, `Армения`, `Грузия` (в базе `RU`, `KZ`, `BY`, `UZ`, `AM`, `GE`) |
| Лимиты Free в день | полигон без лимита, Rush 2, видео 1. У PRO всё `null` |
| Токены | access живёт час, refresh 30 дней, каждый refresh выдаёт новую пару, старый refresh умирает |
| Сутки | По `X-Timezone-Offset` (минуты от UTC, от -720 до 840), сервер запоминает его у игрока |
| Ошибка | HTTP-код и `{"error": {"code", "message", ...доп. поля}}`. 500 тоже в этом формате, код `internal` |
| Коды ошибок | `unauthorized`, `validation_error` (400), `limit_reached`, `pro_required`, `position_locked` (+`daysLeft`), `league_not_found`, `league_name_taken`, `not_league_owner`, `session_expired`, `auth_not_configured`, `not_found`, `method_not_allowed`, `rate_limited` |

## Как работать

1. Прочитай `API.md` целиком, потом `backend/app/v1.py`. Сверяй каждое поле ответа с примером JSON в контракте: имя, тип, `null` против отсутствия поля.
2. Каждый случай оформляй тестом в `backend/tests/` на `unittest` и `TestClient`. Новых тестовых библиотек не добавляй.
3. Каждый тест создаёт своих игроков через `uuid`, чтобы тесты не зависели друг от друга. Базу укажи временной: `store.DB_PATH = Path(tempfile.mkdtemp()) / "x.sqlite"` до импорта `app.main`.
4. Перед каждым тестом очищай `app.main._hits`, иначе упрёшься в лимит 20 входов в минуту с одного IP и 60 запросов в минуту на игрока.
5. Нашёл расхождение с контрактом: напиши падающий тест, исправь код в месте, через которое идут все вызовы, и прогони весь набор. Если правка меняет поведение стенда, обнови и тест стенда, и объясни это в отчёте.

## Что проверить

### 1. Формат ошибок и заголовки

- Каждая ошибка под `/v1` приходит в конверте `error` с `code` и `message`. Проверь 400, 401, 403, 404, 405, 409, 429 и 500.
- Ошибки стенда (без `/v1`) остаются в старом формате `{"detail": ...}`.
- Неизвестный путь `/v1/...` даёт 404 `not_found`, неверный метод даёт 405 `method_not_allowed`.
- Тело не JSON, тело-массив, пустое тело, поле не того типа: всё это 400 `validation_error`.
- `Authorization`: нет заголовка, `Bearer` без токена, `bearer` строчными, чужой токен, токен после logout, токен стенда. Везде 401 `unauthorized`.
- `X-Timezone-Offset`: `180`, `-300`, `+180`, `0`, граница `-720` и `840` проходят. `841`, `-721`, `abc`, `1.5` и пустая строка дают 400. После валидного заголовка сервер хранит значение у игрока.

### 2. Вход и аккаунт

- Google: первый вход создаёт игрока с ELO 800, `position: null`, `provider: google`, email из токена. Повторный вход с тем же `sub` открывает того же игрока и гасит старые токены.
- Apple: имя из `givenName` и `familyName` сохраняется только при первом входе. Проверь имя из одной буквы, имя из 30 символов (обрезается до 20), пустые строки, `null`, перевод строки внутри имени.
- Проверка токена: неверная подпись, чужой `aud`, чужой `iss`, истёкший `exp`, нет `sub`, мусор вместо JWT. Везде 401. Без `GOOGLE_CLIENT_ID` или `APPLE_BUNDLE_ID` сервер отвечает 503 `auth_not_configured`.
- refresh: выдаёт пару `{accessToken, refreshToken}` без других полей. Повтор старого refresh даёт 401. Пустая строка и строка длиннее 64 символов: 401 или 400, но не 500.
- logout: 204, после него и access, и refresh мертвы. logout с мусором тоже 204.
- `DELETE /v1/me`: 204. Пропадают попытки, токены, членство в лигах. Лиги, где игрок создатель, пропадают у всех. Повторный вход тем же `sub` создаёт нового игрока с 800.
- Токен стенда (`/auth/dev-login`) не открывает `/v1`, токен `/v1` не открывает стенд. `dev-login` с внутренним именем игрока приложения даёт 409.

### 3. Объект Me: каждое поле

Для каждого поля из таблицы `Me` в `API.md` проверь значение у нового игрока и после действий, которые его меняют:

| Поле | Новый игрок | Что его меняет |
| --- | --- | --- |
| `name` | `Игрок NNNN` | `PATCH name`, первый вход Apple с именем |
| `position` | `null` | `PATCH position` |
| `positionLockDays` | `null` | смена роли на Free (30), PRO (`null`), течение дней |
| `region` | `null` | `PATCH region` |
| `coach` | `base` | `PATCH coach` на PRO, истечение PRO (снова `base`) |
| `isPro` | `false` | `pro_until` в базе в будущем или в прошлом |
| `elo` | 800 | любая оценённая попытка |
| `positionElo` | `{}` | попытка на роли, ключи в кодах клиента |
| `eloHistory` | восемь раз по 800 | попытки сегодня меняют только последний элемент, `[0]` = ELO до окна |
| `radar` | пять `null` | полигон по оси сцены, Rush ось 3, видео ось 4. После смены роли считаются попытки только новой роли |
| `streak`, `streakWeek` | 0 и семь `false` | задача дня с любым исходом |
| `dailyDone` | `false` | задача дня |
| `daily` | `null` | выбор роли, смена суток |
| `rushBest` | 0 | Rush с большим `solved` |
| `attemptsLeft` | `{polygon: null, rush: 2, video: 1}` | старт режима, PRO |
| `sessionsCount` | 0 | любая завершённая попытка. Старт режима без ответа не считается |

Проверь, что ответ `me` внутри `attempts/*` совпадает с последующим `GET /v1/me` до байта.

### 4. PATCH /v1/me: каждое поле по отдельности и вместе

- `name`: 1 символ, 2, 20, 21, только пробелы, пробелы по краям (обрезаются), эмодзи, перевод строки, табуляция, число вместо строки, `null` (поле не меняется).
- `position`: каждая из 10 ролей клиента. Коды базы (`rb/lb`), верхний регистр (`FB`), пустая строка, число: 400.
- Первый выбор роли не запускает блокировку. Вторая смена на Free запускает 30 дней. Третья смена даёт 403 `position_locked` с `daysLeft`. Смена на ту же роль разрешена всегда. На PRO блокировки нет.
- `region`: шесть допустимых названий. `KZ`, `россия`, `Russia`, пустая строка: 400.
- `coach`: `base` на Free проходит. `pep`, `jose`, `jurgen` на Free дают 403 `pro_required`. Неизвестный тренер: 400.
- Атомарность: если одно поле в запросе неверно, не меняется ни одно. Проверь пары «верное имя и неверный регион», «верное имя и заблокированная роль», «неверный тренер и верная роль».
- Пустое тело `{}` возвращает `Me` без изменений.

### 5. Все роли и все сцены

Для каждой из 10 ролей клиента:

- `PATCH position` сохраняет код базы, а наружу отдаёт код клиента.
- `daily.sceneId` равен роли игрока, `daily` один и тот же весь день.
- Полигон в центр золотой зоны даёт `optimal` и `gold`. Зеркальная сцена с зеркальной точкой (`x → 68 - x`) тоже даёт `optimal`.
- `target: null` даёт `timeout` и `error`, точка за полем (`x = -1`, `y = 200`) даёт `out`.
- `positionElo` получает ключ роли клиента, `radar[axis сцены]` становится 1.0.
- `GET /v1/puzzles/video` для `dm` отдаёт разбор, для остальных 404 `not_found`.

### 6. Полигон и задача дня

- Неизвестный `sceneId`, пустой, длиннее 64 символов: 400.
- `mirrored` строкой `"true"` или числом `1`: 400 (строгие типы). `x` целым числом проходит. `x` строкой, `NaN`, `Infinity`: 400.
- Без выбранной роли: 400.
- `daily: true` с чужой сценой или чужим `mirrored`: 400, рейтинг и серия не меняются.
- Задача дня поднимает `streak` один раз за сутки, повтор в тот же день серию не растит. `streakWeek[6]` становится `true`.
- Ответ содержит `reason`, `eloDelta`, `attempt` и `me`. `attempt.mode = polygon`, `attempt.daily` совпадает с запросом.

### 7. Rush

- `start` без роли: 400. `start` на Free дважды проходит, третий раз даёт 403 `limit_reached`, а `attemptsLeft` идёт 1, 0. На PRO `attemptsLeft: null` и лимита нет.
- Попытка списывается на старте: `me.attemptsLeft.rush` падает сразу после `start`.
- Отправка: пустой `answers` даёт 400, больше 100 ответов тоже 400. Чужой `sessionId`, `sessionId` видео, выдуманный: 400.
- Ответы после третьей ошибки не считаются. Проверь 2 ошибки и 5 золотых (всё считается), 3 ошибки подряд и потом золото (золото отброшено).
- `solved`, `total`, `outcome` спринта: среднее ≥ 0.75 даёт `gold`, ≥ 0.4 `silver`, иначе `error`. `attempt.title` равен `Серия {solved} из {total}`, `axis` равен 3.
- Повтор с тем же `sessionId` возвращает тот же `eloDelta` и `attempt`, ELO не меняется. Проверь и два одновременных запроса из потоков.
- Отправка позже 210 секунд после старта даёт 409 `session_expired`.
- `rushBest` растёт только когда `solved` больше прежнего.

### 8. Видео

- `GET /v1/puzzles/video` не тратит попытку и не отдаёт `correct`, `factors`, `ground_truth`. Варианты приходят в метрах поля.
- `start` без тела, с чужим `puzzleId`, с видео чужой роли: 400. Второй `start` на Free: 403 `limit_reached`.
- `choice`: 0, 1, 2 проходят. 3, -1, `1.0`, `"1"`, `true`: 400.
- `answer`: меньше 10 символов после обрезки пробелов даёт 400, больше 2000 тоже 400.
- Ответ содержит `score` (1..10), `eloDelta`, `review` (`choice` буквой, `answer`, `checklist`, `coach`, `reply`), `correct` и `attempt`. `attempt.outcome = null`, `attempt.score` и `attempt.review` заполнены.
- `review.coach` берётся из профиля: `base` на Free, выбранный тренер на PRO, `base` после истечения PRO.
- Повтор с тем же `sessionId` и другим текстом возвращает первый ответ без второго начисления.
- `puzzleId`, который не совпадает с сессией: 400.

### 9. История попыток

- `GET /v1/me/attempts` отдаёт новые сверху. `limit` ограничен от 1 до 100.
- Пагинация через `nextBefore` проходит все попытки без пропусков и повторов, даже если их создали в одну секунду.
- `before` с `Z`, со смещением `+03:00` и без зоны (считается UTC) работает. Мусор в `before`: 400.
- Старт режима без ответа в истории не появляется.

### 10. Рейтинги

- `global`: игрок есть в `players`, `me.isMe = true`, ранги идут по ELO, при равном ELO выше тот, кто зарегистрировался раньше. Игроки стенда в рейтинг приложения не попадают.
- В `players` всегда есть топ по `limit` и по два соседа сверху и снизу от `me`. Проверь это на 10 игроках и `limit=3`.
- `delta` равна последнему `eloDelta` игрока, у игрока без попыток 0.
- `regional` без параметра берёт регион игрока, при чужом регионе `me` всё равно в ответе. Неизвестный регион: 400.
- Неизвестная таблица: 404.

### 11. Лиги

- Создание: код из 6 символов алфавита `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`. Название от 1 до 32 символов, переводы строк запрещены. Одинаковое название у одного игрока без учёта регистра (и кириллицы) даёт 409 `league_name_taken`, у разных игроков разрешено.
- Вход по коду: строчные буквы принимаются, `O0`, `I1`, 5 и 7 символов дают 400, несуществующий код даёт 404 `league_not_found`. Повторный вход ничего не меняет, `membersCount` не растёт.
- Таблица лиги видна только участникам, остальным 404.
- Переименование, передача прав и удаление доступны только создателю, остальным 403 `not_league_owner`. Передача игроку не из лиги: 400. После передачи бывший создатель остаётся участником и может выйти.
- Создатель не может выйти: 403 `not_league_owner`. После удаления лиги её код не работает, лига пропала у всех участников.
- `myRank` и `membersCount` обновляются после входа, выхода и попыток участников.

### 12. Изменения состояния после ручек

Для каждой ручки, которая что-то меняет, сравни `GET /v1/me`, историю и таблицы до и после запроса. Должно измениться ровно то, что описано в контракте, и ничего больше:

| Ручка | Что меняется | Что не должно меняться |
| --- | --- | --- |
| `PATCH /me` | указанные поля | ELO, попытки, лимиты |
| `POST /modes/*/start` | `attemptsLeft` | ELO, `sessionsCount`, история |
| `POST /attempts/polygon` | ELO, `positionElo`, `eloHistory[7]`, `radar`, `sessionsCount`; при `daily` ещё `streak`, `streakWeek`, `dailyDone` | лимиты Rush и видео |
| `POST /attempts/rush` | ELO, `rushBest`, `radar[3]`, `sessionsCount` | `attemptsLeft` (списан на старте) |
| `POST /attempts/video` | ELO, `radar[4]`, `sessionsCount` | `attemptsLeft` |
| ошибочный запрос любой ручки | ничего | всё |
| `POST /leagues*` | `GET /leagues`, таблица лиги | `Me` |
| `DELETE /me` | игрок исчез из рейтингов и лиг | данные других игроков |

### 13. Время

- Смени `X-Timezone-Offset` так, чтобы у игрока начались новые сутки: лимиты Rush и видео обнуляются, `dailyDone` становится `false`, `daily` может смениться.
- Серия: задача дня вчера и сегодня даёт 2. Пропуск дня обнуляет видимую серию. Время двигай через `created_at` и `last_daily_on` в базе, сервер не трогай.
- PRO с `pro_until` вчера считается Free: лимиты возвращаются, тренер `base`, блокировка роли снова действует.

### 14. Параллельность и злоупотребления

- 5 потоков одновременно жмут `start` Rush у игрока Free: проходят ровно 2.
- 5 потоков отправляют один `sessionId`: ELO меняется один раз, все ответы одинаковые.
- Игрок A не может отправить попытку в сессию игрока B, увидеть таблицу чужой лиги, передать или удалить чужую лигу.
- Больше 60 запросов в минуту от игрока дают 429 `rate_limited`, больше 20 входов в минуту с IP тоже 429.

### 15. Стенд

Весь старый набор `tests/test_journeys.py` и юнит-тесты должны остаться зелёными. Стенд по-прежнему открывается на `/`.

## Что сдать

1. Новые и исправленные тесты в `backend/tests/`, весь набор зелёный.
2. Исправления в коде с объяснением: что было, почему это ошибка по контракту, где правка.
3. Отчёт в таблице «случай → ожидание → факт → статус». Отдельным списком: что не удалось проверить и почему (например, сцены клиента `lib/engine/scenes.dart` недоступны, поэтому совпадение геометрии с клиентом не проверено).
