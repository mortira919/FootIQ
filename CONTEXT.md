# Где мы

Дата среза: 4 октября 2026. Репозиторий: https://github.com/mortira919/FootIQ, ветка `main`.

Стенд крутится локально: `http://127.0.0.1:8000`. База одна, SQLite, файл `backend/data/footiq.sqlite`. Этот файл и `.venv` в git не входят.

## Готово

Игрок входит по имени (`POST /auth/dev-login`). То же имя открывает того же игрока. Новый вход гасит старые токены. Дальше заголовок `Authorization: Bearer`.

На стенде можно выбрать амплуа, решить сцену кликом, закрыть день, пройти раш, отправить видеоразбор, посмотреть историю, радар и топ. Кнопки бьют в живые ручки.

Судья сцены совпадает с клиентскими правилами: поле 68 на 105, атака к меньшему `y`, зеркало, золото, серебро, тень, аут, таймаут. В юнит-тестах ещё нет офсайда, конуса, опеки и «нет адресата».

Рейтинг: Glicko-2, старт 800, RD 350. Первый золотой ответ двигает число сильно, дальше слабее. Запись рейтинга, серии и попытки идёт одной блокировкой, параллельные ответы не затирают друг друга.

Серия растёт от любой задачи дня, один раз за сутки. Сутки считаются в часовом поясе игрока. У текущих записей это `Asia/Almaty`.

Free меняет амплуа раз в 30 дней. PRO включается ручкой `POST /users/me/tier` и живёт 30 дней (`pro_until`). После даты снова Free: замок амплуа возвращается, тренер снова «Ассистент». Пока PRO, видео за день не одно.

Раш: просмотр пачки лимит не тратит. Два сданных спринта в день. Видео на Free: один ответ в день, проверка вместе со вставкой. Повторный разбор после смены роли берёт задачу нового амплуа. Кеш текста привязан к игроку. Правильный вариант видео клиенту не отдаётся.

Есть страна (две буквы), топ общий, региональный и лига. Код лиги сейчас из hex, шесть символов.

Тесты: 32 зелёных, `cd backend && PYTHONPATH=. .venv/bin/python -m unittest discover -s tests`.

Роли в наших сценах: `gk`, `cb`, `rb/lb`, `dm`, `cm`, `am`, `lm/rm`, `lw/rw`, `st`, `ss`. Десять сцен и один видеоразбор `vid-dm-shadow-1`.

## Чего нет

Apple, Google, RevenueCat, Postgres, Redis, CDN, живая модель для видео. Разбор видео считает рубрика по словам. Покупка PRO на стенде это флаг, не чек.

Репозиторий на GitHub всё ещё публичный. Его стоит закрыть: Settings, внизу, Change visibility.

## Следующий шаг

Клиент (Flutter, 28 сентября 2026) описал свой контракт. Игровая логика у нас есть, провод другой.

Он ждёт префикс `/v1`, ключи `camelCase`, ошибки `{"error": {"code", "message"}}`. Стенд отвечает `snake_case` и полем `detail`.

Первым делом не выкидывать стенд, а добавить слой `/v1` поверх того же судьи и Glicko:

1. `POST /v1/auth/device` с `deviceId`, плюс `refresh`. Старые сейвы тестеров не переносим, старт с 800.
2. `GET /v1/me` одним ответом: ELO, ELO по ролям, серия, неделя серии, `dailyDone`, остаток раша и видео, `positionLockDays`, радар из пяти чисел от 0 до 1, график из 8 точек. Ранг клиент считает сам. Его пороги: Новичок с 0, Любитель с 1000, Полупрофи 1200, Профи 1400, Элита 1600, UEFA Pro с 1800.
3. Сутки по заголовку `X-Timezone` на каждом запросе.
4. Регионы в API кодами: `RU`, `KZ`, `BY`, `UZ`, `AM`, `GE`.
5. Свести коды ролей. У клиента `fb`, `wm`, `winger`. У нас `rb/lb`, `lm/rm`, `lw/rw`. Пока коды разные, сцены не совпадут.
6. Раш по его правилам: `sessionId`, попытка списывается на старте, 3 минуты, 3 жизни, одна отправка рейтинга на спринт.
7. Видео: тренер из профиля (`base`, `pep`, `jose`, `jurgen`), повтор того же `sessionId` не списывает попытку второй раз.

Пока слой `/v1` не сделан, описание «что приходит на какой экран» писать рано: цифры стенда и цифры клиента разъедутся.
